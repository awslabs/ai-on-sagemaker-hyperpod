# What's Next

You now have a detailed understanding of the training stages across three model families — from the LLM forward pass (embedding through attention and FFN to logits), through vision architectures (ViT, CoCa) and VLM fusion strategies, to VLA action tokenization for robotics. Here's where to go from here.

---

## The Backward Pass

After the forward pass produces logits and the loss is computed, `loss.backward()` triggers **backpropagation**: PyTorch's autograd engine walks the computation graph in reverse, computing the gradient of the loss with respect to every parameter.

The key insight: the backward pass traverses the **exact same operations** as the forward pass, but in reverse order and computing gradients instead of activations. This is why understanding the forward pass is prerequisite to understanding distributed training — the backward pass mirrors it.

```
Forward:  Embedding → Layer 1 → Layer 2 → ... → Layer 36 → lm_head → Loss
Backward: Loss → lm_head → Layer 36 → ... → Layer 2 → Layer 1 → Embedding
```

During the backward pass through each transformer block:
1. Gradients flow through the FFN (3 matrix multiplications, reversed)
2. Gradients flow through the attention mechanism (including softmax, masking, scaling)
3. Gradients flow through RMSNorm
4. **Residual connections** provide a direct gradient path that bypasses these operations

## KV Cache During Inference

During autoregressive **inference** (generating text token by token), the model processes one new token at a time. Without optimization, this would require recomputing K and V for all previous tokens at every step.

The **KV cache** stores the K and V tensors from all previous tokens, so only the new token's Q, K, V need to be computed:

```
Step 1: Compute K, V for token 0 → cache K[0], V[0]
Step 2: Compute K, V for token 1 → cache K[1], V[1]
        Attend Q[1] against cached K[0:2], V[0:2]
Step 3: Compute K, V for token 2 → cache K[2], V[2]
        Attend Q[2] against cached K[0:3], V[0:3]
...
```

This is where **GQA's 4x KV cache reduction** directly translates to longer context windows or larger batch sizes during inference.

## Advanced Topics to Explore

### FlashAttention
Fuses the entire attention computation into a single GPU kernel, avoiding the materialization of the `(seq_len, seq_len)` attention matrix. Essential for long-context training and inference.

### Tensor Parallelism
Splits individual weight matrices across GPUs. For example, `W_Q` (4096 x 4096) can be split column-wise across 4 GPUs, with each GPU computing a quarter of the Q heads.

### Pipeline Parallelism
Different transformer layers run on different GPUs. GPU 0 handles layers 1-9, GPU 1 handles layers 10-18, etc. The forward pass becomes a pipeline across devices.

### FSDP (Fully Sharded Data Parallel)
Shards all parameters across GPUs and gathers them just-in-time for each layer's forward pass. After the forward pass through a layer, the parameters are discarded and re-gathered during the backward pass.

### Mixed Precision Training
Qwen3 8B uses `bfloat16` for weights and activations but `float32` for the optimizer state and loss scaling. Understanding which operations happen in which precision ties directly back to the forward pass.

## Multimodal & Embodied AI Frontiers

### Efficient Attention for Vision
The quadratic cost of self-attention is the central scaling bottleneck for VLMs. Active research directions include:
- **Linear attention** — replace softmax attention with kernel-based approximations that run in O(n) time.
- **Token pruning/merging** — dynamically drop or merge uninformative visual tokens during the forward pass.
- **Windowed attention** — apply attention only within local windows (Swin Transformer), then aggregate globally.

### Multimodal RLHF
Aligning VLMs with human preferences is harder than text-only RLHF because:
- Evaluators must judge visual faithfulness (does the answer match the image?) in addition to text quality.
- Hallucination is a visual-specific failure mode that text-only reward models can't detect.
- Training data for multimodal reward models is scarce and expensive to annotate.

### Unified Multimodal Architectures
The trend is moving from "bolt vision onto an LLM" toward natively multimodal models (Gemini, Chameleon) that process interleaved text, images, audio, and video in a single token stream. These models skip the separate ViT + projector pattern entirely, but require vastly more pretraining compute.

### World Models for Robotics
VLAs today produce actions reactively (one observation → one action). The next frontier is **world models** — models that can simulate the future consequences of actions, enabling planning and reasoning before acting. This is critical for complex manipulation tasks where trial-and-error is expensive or dangerous.
