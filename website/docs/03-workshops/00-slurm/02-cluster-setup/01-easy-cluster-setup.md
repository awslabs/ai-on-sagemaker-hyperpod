# Easy Cluster Setup

## Overview

In this section, we provide you with a [script](https://github.com/awslabs/awsome-distributed-ai/blob/main/architectures/sagemaker-hyperpod-slurm/automate-smhp-slurm/automate-cluster-creation.sh) that will walk you through the following:

1. Installing the right packages in your environment (e.g., AWS CLI)
2. Installing the [Lifecycle Scripts](https://github.com/awslabs/awsome-distributed-ai/tree/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config) used by HyperPod nodes during bootstrapping
3. Creating the cluster configuration, and uploading all your assets to Amazon S3 for cluster creation

:::note Asks when you run this script
The script guides you through the entire onboarding process so you can create a SageMaker HyperPod SLURM cluster by yourself. There are detailed instructions and questions. Please read through the descriptions, and make sure your answers conform to the suggested format(s).
:::

## Important Information

You will be asked questions by the script for customizing your HyperPod cluster. For example:

```bash
# In this example, you are asked to input the instance type for your cluster's worker group.
# The default value is ml.g5.8xlarge
Enter the instance type for your worker group [ml.g5.8xlarge]:
```

Since this is a workshop session, the default values are pre-configured for you. You may hit **ENTER** for every question asked by the script!

## Setup Environment

To run this automation script, clone [awsome-distributed-ai](https://github.com/awslabs/awsome-distributed-ai) and run it on your provided CodeEditor terminal. It is recommended to run this script from your own directory, rather than running `cd` into the cloned repository directory.

```bash
# Clone the repository
mkdir hyperpod && cd hyperpod
curl -O https://raw.githubusercontent.com/awslabs/awsome-distributed-ai/refs/heads/main/architectures/sagemaker-hyperpod-slurm/automate-smhp-slurm/automate-cluster-creation.sh

# Run the script
bash automate-cluster-creation.sh
```

Once you get through the script, you should see a directory that looks like:

```
hyperpod/
|-- automate-cluster-creation.sh       # This script!
|-- awsome-distributed-ai/             # The script clones the repo with all the Lifecycle Scripts!
|-- cluster-config.json                # Cluster configuration generated by this script. Run `vi cluster-config.json` to make changes
|-- create_config.sh                   # The shell script used to write your environment variables
|-- env_vars                           # Your environment variables used to create the SMHP cluster
|-- provisioning_parameters.json       # The provisioning parameters file (already uploaded to S3)
|-- validate-config.py                 # Python script that checks whether the created cluster configuration is valid
`-- ...
```

:::important
The last input of the script gives you the option on whether or not you want the cluster created for you. The default option is `yes` unless you submit `no`. Hit **ENTER** to let the script create your HyperPod cluster for you. If you did not hit ENTER, paste the following command:

```bash
aws sagemaker create-cluster \
  --cli-input-json file://cluster-config.json \
  --region $AWS_REGION
```
:::

## Monitor Cluster Creation Status

You can check the status of your cluster using either the SageMaker console, or the command below. Feel free to add a `watch -n 1` before this to refresh the output every second.

```bash
aws sagemaker list-clusters --output table
```

Cluster creation typically takes **12-15 minutes**.

You'll see output similar to the following:

```
-------------------------------------------------------------------------------------------------------------------------------------------------

+-----------------------------------------------------------------------------------------------------------------------------------------------+

|+----------------------------------------------------------------+----------------------+----------------+------------------------------------+|
||                           ClusterArn                           |     ClusterName      | ClusterStatus  |            CreationTime            ||

|+----------------------------------------------------------------+----------------------+----------------+------------------------------------+|
```

The main files that will be used are the `cluster-config.json` and `provisioning_parameters.json`. Note: `provisioning_parameters.json` is already uploaded to S3 as part of the script.

:::tip Want to change the cluster configuration?
If you'd like to make changes to the `cluster-config.json` and `provisioning_parameters.json`, you can open them up in a text editor like `vim` and make the changes. If you make any changes to the `provisioning_parameters` file, please make sure you upload it to S3.

```bash
source env_vars

# copy to the S3 Bucket
aws s3 cp provisioning_parameters.json s3://${BUCKET}/src/

# verify that the files were copied to S3
aws s3 cp s3://${BUCKET}/src/provisioning_parameters.json -
```
:::

### Lifecycle Scripts (LCS)

:::note Optional read
SageMaker HyperPod uses a collection of [lifecycle scripts](https://github.com/awslabs/awsome-distributed-ai/tree/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config) to bootstrap the cluster. These scripts are responsible for setting up Slurm, mounting the FSx Lustre filesystem, among other actions. A description of what each script does is included below:

| Script | Description |
|---|---|
| [config.py](https://github.com/awslabs/awsome-distributed-ai/blob/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config/config.py) | Configuration file for the lifecycle scripts. |
| [lifecycle_script.py](https://github.com/awslabs/awsome-distributed-ai/blob/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config/lifecycle_script.py) | This is the main entrypoint, sets everything else up. |
| [on_create.sh](https://github.com/awslabs/awsome-distributed-ai/blob/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config/on_create.sh) | Entrypoint for clusters. This script calls `lifecycle_script.py`. |
| [fsx_ubuntu.sh](https://github.com/awslabs/awsome-distributed-ai/blob/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config/utils/fsx_ubuntu.sh) | Maps home directory to `/fsx`. |
| [setup_mariadb_accounting.sh](https://github.com/awslabs/awsome-distributed-ai/blob/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config/setup_mariadb_accounting.sh) | Sets up Slurm Accounting with a local mariadb server running on the HeadNode. |
| [setup_rds_accounting.sh](https://github.com/awslabs/awsome-distributed-ai/blob/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config/setup_rds_accounting.sh) | Sets up Slurm Accounting with an RDS endpoint. |
| [setup_sssd.py](https://github.com/awslabs/awsome-distributed-ai/blob/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config/setup_sssd.py) | Sets up Active Directory/LDAP integration with SSSD. |
| [install_docker.sh](https://github.com/awslabs/awsome-distributed-ai/blob/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config/utils/install_docker.sh) | *(enabled by default)* Installs docker, and sets data-root to `/opt/dlami/nvme` if available. |

| [start_slurm.sh](https://github.com/awslabs/awsome-distributed-ai/blob/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config/start_slurm.sh) | Starts the Slurm scheduler daemon. |
| [add_users.sh](https://github.com/awslabs/awsome-distributed-ai/blob/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config/add_users.sh) | *(optional)* Creates posix users specified in a file `shared_users.txt`. |
| [shared_users_sample.txt](https://github.com/awslabs/awsome-distributed-ai/blob/main/1.architectures/5.sagemaker-hyperpod/LifecycleScripts/base-config/shared_users_sample.txt) | Sample of how to specify users for the `add_users.sh` script. |
| `provisioning_parameters.json` | Defines scheduler type Slurm and sets the partitions up. This is created by the automation script. |

### Observability

:::note Optional read
This section shows you what changes are made if you answer `yes` to `Did you deploy the optional hyperpod-observability CloudFormation stack? (yes/no)`.

If you deployed the optional [hyperpod-observability](https://github.com/awslabs/awsome-distributed-ai/tree/main/observability/prometheus-grafana) CloudFormation stack during the pre-requisites for this workshop, enable installation of exporter services on the cluster by setting `Config.enable_observability` to `True` in `base-config/config.py`. This will install the exporter services on the cluster to emit metrics to Amazon Managed Prometheus.

```python
# Basic configuration parameters
class Config:
    ...
    # Set true if you want to install metric exporter software and Prometheus for observability
    # DCGM Exporter and EFA Node Exporter are installed on compute nodes,
    # Slurm Exporter and Prometheus are installed on controller node.
    enable_observability = True
```

**Modify AmazonSagemakerClusterExecutionRole**

Additionally, it is required to add the following 2 AWS managed IAM policies to your [AmazonSagemakerClusterExecutionRole](https://console.aws.amazon.com/iam/home?#/home) prior to creating your cluster:

- `AmazonPrometheusRemoteWriteAccess` — permissions to allow prometheus remote-write on cluster to send metrics to Amazon Managed Prometheus.
- `AWSCloudFormationReadOnlyAccess` — permissions to fetch the Prometheus remote write URL used in the prometheus config on the controller node.

```bash
aws iam attach-role-policy --role-name $ROLENAME --policy-arn arn:aws:iam::aws:policy/AmazonPrometheusRemoteWriteAccess
aws iam attach-role-policy --role-name $ROLENAME --policy-arn arn:aws:iam::aws:policy/AWSCloudFormationReadOnlyAccess
```
:::
